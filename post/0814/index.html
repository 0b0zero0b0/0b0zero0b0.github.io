crux(关键) 问题–如何将资源虚拟化

  • 目的：让系统易于使用

  • 标准库–OS提供的给应用程序调用的来运行程序、访问内存和设备的数百个系统调用

虚拟化CPU

  • 将单个CPU转换为看似无限数量的CPU->许多程序看似同时运行

虚拟化内存

  • 访存

5.1 fork()系统调用

  • fork()创建子进程
    • 子进程直接从fork()系统调用返回
    • 拥有自己的地址空间、寄存器、程序计数器…
    • 父进程获得的返回值为子进程的PID–子进程获得的为0
    • CPU调度程序决定某一时刻哪个进程在执行

5.2 wait()系统调用

  • 父进程调用wait()–会等待子进程运行结束后才继续

5.3 exec()系统调用

  • 使父子进程分别执行不同的程序
  • 给定可执行程序名称和需要参数–exec()从可执行程序中加载代码和静态数据–覆写自己的代码段，堆、栈及其他空间内存均重被初始化–OS执行该程序，将参数通过argv传递给该进程
  • 直接将当前运行程序替换为不同的运行程序–未创建新进程
  • 不会返回对exec()的成功调用

5.4 为什么这样设计API

  • 分离fork()和exec()的设计

    • 给了shell在fork之后和exec之前执行代码的机会–可在新程序运行前改变环境

  • e.g.，shell

    1. 显示提示符，等待用户输入(可执行程序名称+参数)
    2. shell找到该程序
    3. 调用fork()创建新进程
    4. 调用exec()的某个变体执行该程序
    5. 调用wait()等待命令完成
    6. 子进程结束后，shell从wait()返回并再出输出提示符

  • shell-重定向

    • 在调用exec()前关闭标准输出，打开定向的文件

  • pipe()系统调用

    • 一个进程的输出被链接到了一个内核管道(pipe)上(队列)，另一个进程的输入也被链接到了同一个管道上

    2. 控制权–有效运行进程+保留对CPU控制权

  • crux：如何高效、可控地虚拟化CPU

6.1–基本技巧：受限直接执行

  • 直接执行–直接在CPU上运行程序

6.2–问题1：受限制的操作

  • crux：如何执行受限制的操作

    • 采用受保护的控制权转移
      • 用户模式–部分访问硬件资源
      • 内核模式–完全访问
        • 陷入内核(trap)
        • 从陷阱返回

  • 让所有进程做所有它想做的事情–无法构建需求的系统–保护失效

  • 新的处理器模式

    • 用户/内核模式–用户模式的进程不能发出I/O请求
    • 当用户希望执行某种特权操作–程序执行陷阱指令–跳入内核并提升至内核模式–执行系统调用(被允许的部分关键功能)后从陷阱返回至用户模式
    • 陷阱–需确保存储足够的调用者寄存器，使得最终能够正确返回–进程内核栈

  • 陷阱获取OS内运行的目标代码

    • 指定跳转地址–不可行、危险操作–会使程序随意跳转内核任意位置
    • 设置陷阱表(内核启动时)–OS会告诉硬件发生异常事件时要运行的代码
    • 告知硬件陷阱表的位置–特权操作

  • LDE协议–受限直接运行

    1. 内核初始化陷阱表–CPU记住其位置–系统引导时
    2. 内核对进程初始化–切回用户模式执行–需要系统调用，陷入OS，执行完返回–进程执行结束，正确退出(可能涉及exit()系统调用)–OS清除该进程–运行进程时
